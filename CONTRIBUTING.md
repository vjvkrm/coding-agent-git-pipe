# Contributing

Thanks for contributing to `agent-pipe`.

## Before you start

- Use Node.js `18+`.
- Work from a clean git repository.
- Install dependencies with `npm install`.
- Build the project with `npm run build`.
- Run tests with `npm test`.

## Development workflow

1. Create or switch to a branch for your change.
2. Make focused changes that solve one problem at a time.
3. Keep edits consistent with the existing TypeScript style.
4. Run `npm run build` and `npm test` before opening a PR.
5. Update `README.md`, `API.md`, or `pending.md` when behavior or project status changes.

## Repository layout

- `src/`: TypeScript source for the CLI, orchestrator, adapters, and helpers.
- `tests/`: Node test runner coverage for CLI behavior and core modules.
- `dist/`: compiled output generated by `npm run build`.
- `bin/`: published CLI entrypoint.
- `pending.md`: roadmap and remaining work.

## Commands

- `npm run build`: compile TypeScript into `dist/`.
- `npm test`: run the test suite.
- `npm run dev -- run "your task"`: run the CLI from source.
- `npm run run -- "your task"`: run the built CLI.

## Coding guidelines

- Prefer small, root-cause fixes over broad refactors.
- Avoid unrelated changes in the same patch.
- Preserve the plan → implement → review contract flow.
- Keep handoff messages compact and technically specific.
- Add or update tests when changing behavior covered by the test suite.

## Config and agent changes

If you change routing, adapters, or contract handling:

- Update docs in `README.md` and `API.md` when user-visible behavior changes.
- Keep `.agentpipe.json` examples aligned with actual config behavior.
- Verify fallback and human-escalation paths still make sense.

## Pull requests

Good PRs usually include:

- a short description of the problem,
- the concrete fix,
- any tradeoffs or follow-up work,
- and the validation you ran.

If your change is intentionally incomplete, note the next step clearly in `pending.md` or the PR description.
